# Authoring `platform/`

Everything in this directory is yours and is version controlled. This is the
reference; [the README](../README.md) is the tour.

## What goes where

```text
platform/
  typescript/
    src/endpoints/**   PingIDM custom endpoints        → tier 1, ~1 s
    src/tasks/**       standalone PingIDM scripts      → tier 1, ~1 s
    src/scripts/**     PingAM scripted decision nodes  → tier 2, ~22 s
    framework/**       the authoring surface (managed — see below)
    tests/**           node:test, run by `fo check`
  idm/conf/**          PingIDM config JSON             → tier 1, ~1 s
  idm/script/**        GENERATED from src/ — never edit
  amster/config/**     journeys, OAuth2 clients, …     → tier 2, ~22 s
  am/config/**         PingAM file-based config        → tier 3, ~51 s
```

The tier is decided by the *directory*, not by you: `fo dev` watches all of
them and fires the cheapest mechanism that can deliver the change. `fo watch`
does the same without Tilt.

`platform/idm/script/` and `platform/idm/conf/endpoint-*.json` are build output
and are gitignored. If you find yourself editing one, the file you want is in
`src/`.

Deleting a source file removes it properly: `fo build` retires the generated
output, and the next `fo sync` deletes it from the running pod too, so the
endpoint stops answering. Only files carrying `fo build`'s own generated
marker are eligible for that, so nothing you or PingIDM put there is at
risk.

## Managed, seeded, yours

Three kinds of file live side by side, distinguished by a header comment and
tracked by content hash in `.fo/packages.lock`:

| Kind | Example | What `fo upgrade` does |
| --- | --- | --- |
| **Managed** | `framework/**`, the tsconfigs | Nothing, today — see below. Treat as overwritable. |
| **Seeded** | `src/endpoints/hello.ts` | Leaves it alone once you have changed it. |
| **Yours** | everything you add | Never touched. |

Read the header comment before editing. "Managed file — regenerated by
`fo upgrade`" states the CONTRACT, not current behaviour: `fo upgrade` does not
re-seed managed files at present, and cannot, because `fo` and the workspace
are the same tree here so there is nothing to copy from. That changes with
`fo init`, which would create a workspace separate from the tool; the
content-hash machinery it needs already exists in `.fo/packages.lock`.

So an edit to `framework/**` survives an upgrade today and is still a bad idea:
the contract is what the next version will enforce, and nothing warns you when
it starts.

## A PingIDM endpoint

One file in `src/endpoints/` per endpoint. The file name is the route: `hello.ts`
becomes `/openidm/endpoint/hello`.

```ts
import { defineEndpoint, route, v } from "../../framework/index.ts";

export default defineEndpoint({
  name: "greet",                       // must match the file name
  summary: "Greeting",
  headers: { "x-request-id": v.optional(v.uuid()) },
  routes: [
    route({
      method: "read",
      path: "/{name}",
      params: { name: v.string({ minLength: 1, maxLength: 64 }) },
      query: { shout: v.optional(v.boolean()) },
      response: v.object({ _id: v.string(), message: v.string() }),
      handler: ({ params, query, log }) => {
        log.debug("greeted a caller", { name: params.name });
        const message = "hello, " + params.name;
        return {
          _id: params.name,
          message: query.shout === true ? message.toUpperCase() : message,
        };
      },
    }),
  ],
});
```

**Nothing in the handler is annotated.** `params.name` is `string` because the
validator says so, and `query.shout` is `boolean | undefined` because it is
optional. Tighten a validator and the handlers that relied on the old shape
stop compiling — which is the point of the whole arrangement.

`route()` takes `read`, `create`, `update`, `patch`, `delete` or `action`.
`method: "query"` is deliberately rejected there — a query returns a paged
envelope rather than a resource, so it has its own constructor:

```ts
queryRoute({
  path: "/",
  query: { style: v.optional(v.enumOf(["hello", "g'day"] as const)) },
  response: GREETING,
  handler: ({ query }) => queryResult([{ _id: "hello", message: "hi" }]),
});
```

### Validators

`v` is the whole surface: `string`, `integer`, `number`, `boolean`, `uuid`,
`isoDate`, `enumOf`, `object`, `record`, `list`, `csv`, `patchOperations`,
`unknownValue`, and the modifiers `optional`, `nullable`, `withDefault`.

They do three jobs at once — runtime parsing, the handler's static types, and
the OpenAPI document `fo build` emits — so there is exactly one place to state
what a field is.

`nullable` and `optional` are different questions. `optional` is about whether
the key is *present*; `nullable` is about whether the value may be `null`.
PingIDM will hand you both.

### Faults, not Errors

```ts
throw badRequest("There is no greeting for nobody.", { name: params.name });
```

Never `class MyError extends Error`. PingIDM's script engine has no `Reflect`,
so Babel's `_wrapNativeSuper` produces a class whose `instanceof` silently
returns false — the handler compiles, deploys, and mis-routes its own errors at
runtime. A lint rule rejects the alternative. Use `badRequest`, `unauthorized`,
`forbidden`, `notFound`, `methodNotAllowed`, `conflict`, `internalError`, or
`fault()` for anything else.

### Logging

`log` on the handler context is a request logger: it carries the endpoint, the
route and the correlation id, so you do not restate them.

```ts
log.debug("greeted a caller", { name: params.name });
```

Prefer this to the bare `logger` global. `fo trace` can only line your line up
with PingAM's if it carries the transaction id, and the request logger does.

## A PingIDM task

For work PingIDM invokes by file rather than over HTTP — scheduled jobs, mostly.
No routing, no validation, no `conf/` binding; the return value is the result.

```ts
import { defineTask } from "../../framework/task.ts";

export default defineTask({
  name: "flag-stale-accounts",         // must match the file name
  main: () => {
    const found = openidm.query("managed/user", { _queryFilter: "true" });
    return { checked: found.result.length };
  },
});
```

`_queryFilter` is required by the type, because PingIDM rejects a query without
one — and requiring it also catches the misspelling that would otherwise
silently return everything.

**What `openidm.query` returns is not what a query handler may return.**
PingIDM omits `remainingPagedResults` from its own results but *requires* it on
yours, failing with `Script returned unexpected query result structure`. The
two are separate types so that passing one straight through is a compile error;
build the response with `queryResult(rows)`.

## A PingAM script

`src/scripts/` is a **separate TypeScript program** (`tsconfig.am.json`),
because PingAM and PingIDM declare colliding globals — both have a `logger`,
and they are not the same shape. A file that imports from
`framework/index.ts` will not compile here, and should not.

They do share a `lib`, because they share an engine: both were probed on a
running stack, 767 probes each, and differ in only two places nothing here
uses. That sharing is sound because each program is checked against its
own engine, not because the two engines are the same object. So
`Object.entries`, `String#padStart` and `Promise#finally` are available in
both; `Array#flat`, `Object.hasOwn`, `String#replaceAll`, `Proxy` and
`Reflect` are in neither, and will not compile. Nothing is polyfilled, so that
list is the truth rather than a house style.

A second class of thing compiles and then throws, and it needs a different
answer. 234 of the 728 declarations the pinned `lib` carries are absent from
PingAM's Rhino (232 from PingIDM's) — the typed arrays almost entirely
(`Float32Array` has `get`, `set` and `subarray` and nothing else), plus
`RegExp#flags`, `RegExp#sticky` and `Date#[Symbol.toPrimitive]`. They cannot be
removed: `lib.es5` is one file, and declaration merging can add a member but
never subtract one. So **`fo build` resolves the builtin references it can, in
both programs, and fails before it emits anything**, naming the file and line — the
same step that runs the type-check, so the error arrives in your editor rather
than from a later test run.

That check resolves property access, element access with a literal or
finite-union key, binding patterns, destructuring assignment and well-known
symbol members. It cannot see `obj[key]` where `key` is a plain `string`, or a
concrete type erased behind a structural generic; `tools/engine-usage.mjs`
states the boundary rather than implying there isn't one.

```ts
import { defineAmScript } from "../../framework/am.ts";

export default defineAmScript({
  name: "risk-login-check",            // must match the file name
  context: "SCRIPTED_DECISION_NODE",
  outcomes: ["low", "high"],
  main: function (action) {
    // `nodeState.get` returns the raw value: it may be null, and it is a Java
    // String rather than a JavaScript one, so coerce it before calling
    // anything on it.
    const collected = nodeState.get("username");
    const username = collected == null ? "" : String(collected);
    action.goTo(username.indexOf("svc-") === 0 ? "high" : "low");
  },
});
```

`fo add example-risk-login` installs a complete, working version of this
alongside the journey that calls it.

`outcomes` is not documentation: PingAM draws the node's exits from it, and a
`goTo` naming an outcome you did not declare dead-ends at runtime — in front of
a real user, with nothing useful in the AM log and a successful `fo amster`
behind it.

So `action` is **handed to `main`**, typed to exactly the outcomes you declared
just above it. `action.goTo("hihg")` does not compile, and neither does
`action.goTo(risky ? "high" : "hihg")` — which matters, because the second one
is invisible to any check that reads the built artefact looking for quoted
outcome names.

Write `outcomes` as a literal array. Both `outcomes: [...names]` and
`outcomes: ["high", ...names]` are rejected: AM needs the exits statically, and
a spread widens the outcome type to `string`, which switches every check above
off without changing a line of `main`.

And let `main`'s parameter be **inferred**. Annotating it replaces the narrowed
type, and TypeScript accepts a wider `{ goTo(outcome: string): void }` because
it compares method parameters bivariantly — no amount of care in `AmAction`
prevents that. `fo build` rejects an annotated parameter instead, which is the
only place it can be caught.

PingAM also puts a bare `action` in global scope. That one is declared as
accepting no outcome at all, so reaching for it is a compile error rather than
a way around the check. Take the parameter.

The build emits an amster `Scripts` entity, so an AM script deploys through
tier 2 (`fo amster`), not by syncing a file into a pod.

## Managed-object types

`platform/idm/conf/managed.json` is the source of truth for your object model,
and `fo config export idm` keeps it current. `fo build` generates
`src/generated/managed.ts` from it, which augments `openidm.read` and friends:

```ts
const user = openidm.read("managed/user/" + id);   // typed as ManagedUser
user.givenName;                                     // string | null
```

Optional properties are `T | null`, not `T | undefined`, because PingIDM
returns JSON `null` for a cleared property rather than omitting the key.

The generated file is committed, and a test fails if it drifts from
`managed.json`. Run `fo build` after changing the schema.

## Testing

`platform/typescript/tests/**` runs under `node:test` as part of `fo check`.
Tests import the framework directly; there is no PingIDM to stand up.

The trap worth naming: a test that re-states the rule it is checking proves
only that it agrees with itself. If the code under test reaches for `openidm`,
split the decision out as a pure function and point the test at *that* — not
at a copy of it in the test file.

## The gates

```sh
fo check     # types (fo and platform), lint, tests, build
fo build     # just the compile-and-emit pipeline
```

`fo check` type-checks three programs (the endpoints, the AM scripts, the
tests), lints, runs both test suites, and builds. Nothing is emitted unless
every step succeeds for every entry point, so a broken build never leaves
half-updated output for `fo sync` to push.

## Config files, not code

`platform/idm/conf/**` is plain PingIDM config JSON, synced into the running
pod and picked up by its file watcher — no restart, typically under a second.

`platform/amster/config/**` is amster export format. **An amster import
replaces an entity; it does not merge into it.** Anything you leave out reverts
to the schema default, which is often `null` — so a sparse OAuth2 client works
on first import and breaks on the second, once your file has overwritten the
defaults PingAM filled in. Spell out every field you depend on, or let
`fo config export am` write a complete one.

`platform/am/config/**` is PingAM's file-based config. It does not exist until
you run `fo config export am`; until then PingAM boots from its own image. Once
it exists, `fo` builds it into a config-profile image on every `fo up` and
`fo restart am`, because the init container that installs it would otherwise
re-copy the config it copied last time.
